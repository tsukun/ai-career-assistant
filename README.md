# AI職務経歴書アシスタント

## 概要

職務経歴を入力すると、生成AIを利用して以下の内容を分析するWebアプリケーションです。

- 職務経歴の要約
- 技術的な強み
- 面接でアピールすべきポイント
- 今後伸ばすべきスキル

個人開発を通して、Java / Spring BootによるWebアプリケーションへ生成AIを組み込む方法を学習することを目的として開発しています。

---

## 開発目的

既存のJava / Spring BootによるWeb開発経験を活かしながら、生成AIをWebアプリケーションへ組み込むための技術を実際に学習・検証することを目的として開発しました。

以下の技術について、実際にシステムへ組み込みながら理解を深めています。

- Spring AI
- LLM
- プロンプト設計
- LLMとの連携
- 入力値バリデーション
- AI連携時のエラー処理
- Git / GitHub

単純に生成AIを利用するだけではなく、Webアプリケーションの一機能としてLLMを組み込み、設計・実装・動作確認まで一通り経験することを重視しています。

## Spring AI

LLMとの連携にはSpring AIを利用しています。

Spring AIを利用することで、Spring BootアプリケーションからLLMを扱うための仕組みを利用でき、LLMとの連携処理をアプリケーションの処理から分離しやすい構成としています。

既存のJava / Spring Bootによる開発経験を活かしながら、Springベースのアプリケーションに生成AIを組み込む方法を学習することを目的として採用しました。

また、AIとの連携部分をアプリケーション内で分離することで、将来的に利用するLLMや接続先を変更する場合にも対応しやすい構成を意識しています。

---

## Ollama

LLMの実行環境としてOllamaを利用しています。

個人開発において、ローカル環境でLLMを実行しながら生成AIとの連携を検証できる点を考慮して採用しました。

主な利点として以下を考えています。

- ローカル環境でLLMを実行できる
- API利用料をかけずに検証できる
- LLM連携の仕組みを実際に構築できる
- 外部サービスへデータを送信せずに検証できる

特に本アプリケーションでは職務経歴を入力データとして扱うため、開発・検証段階ではローカル環境で完結できる構成としています。

---

## Qwen3.5 9B

Ollama上で利用するLLMとしてQwen3.5 9Bを採用しています。

個人PC上で実行することを前提としているため、モデルの性能だけではなく、ローカル環境で実行可能なサイズとのバランスを考慮して選択しています。

本開発ではLLMそのものの性能を追求することよりも、LLMをWebアプリケーションへ組み込む一連の流れを実際に構築・検証することを重視しています。

## 主な機能

### 職務経歴分析

入力した職務経歴を生成AIへ渡し、以下の内容を生成します。

- 職務経歴の要約
- 技術的な強み
- 面接でアピールすべきポイント
- 今後伸ばすべきスキル

アプリケーションの用途に合わせてプロンプトを設計し、ITエンジニアの転職活動で利用することを想定した分析を行います。

---

### 事実抽出

職務経歴から記載されている事実を抽出する機能を実装しています。

抽出対象には以下のような情報があります。

- 経験年数
- 業務内容
- 担当システム
- 担当工程
- 使用技術
- システム間連携
- 担当した役割
- 成果
- 資格
- チーム規模

抽出した事実を構造化し、その情報をもとにAI分析を行う構成としています。

入力された職務経歴に明記されている情報を基準として分析することで、AIによる不要な推測を抑えることを意識しています。

---

## プロンプト設計

AI分析では、アプリケーションの用途に合わせてLLMへの指示を設計しています。

主に以下のような内容を指定しています。

- ITエンジニアのキャリア分析を目的とする
- 職務経歴を要約する
- 技術的な強みを抽出する
- 面接でアピールすべきポイントを提示する
- 今後伸ばすべきスキルを提示する
- 転職活動で利用することを想定する
- 具体的かつ簡潔に回答する

生成AIを単純に呼び出すだけではなく、**システムの目的に合わせてプロンプトを設計すること**を意識しています。

---

## 入力バリデーション

Spring BootのValidation機能を利用しています。

- 職務経歴の未入力チェック
- 10,000文字以内の入力制限

入力内容に問題がある場合はLLMへのリクエストを送信せず、アプリケーション側でエラーとして処理します。

---

## AIエラーへの対応

LLM連携では、モデルが起動していない場合やLLMとの通信に失敗した場合などを考慮する必要があります。

本アプリケーションではSpring AIのリトライ機能を利用してAI連携時のエラーに対応しています。

また、リトライ回数を設定ファイルで制限しています。

```properties
spring.ai.retry.max-attempts=1
```

これにより、LLMが利用できない場合に不要なリトライが継続することを防いでいます。

      ↓

### Controller

HTTPリクエストを受け取り、入力値のバリデーションを行います。

### Service

### DTO

リクエスト・レスポンスのデータ構造を定義しています。

Web層とAI連携処理を分離し、それぞれの責務を分けた構成としています。
